これまでの開発の推移を説明する、

### 以下時系列順
1
過去の経験から学習に関するサービスを作りたい
ユーザーに最適なロードマップを作成するサービスを作ろう
-アダプティブラーニングの存在を知る
アダプティブラーニングを取り入れればいいのでは
アダプティブラーニングを自分なりに解釈

2
設計書をgptと一緒に作り出す
作成途中、作りたいものが、
ロードマップを提示するものから
自分が好んでいる(重要視している)学習方法=自主的に考えること
を取り入れたいとgptとの対話を通して考え出す
=>作りたいものが、楽に効率的に学習するものから、自主性と効率の両立したものになる

その変化により、設計書を作っているつもりが設計思想書を作る状態へと気づかずに変化
その後サービスに必要な概念をgptと相談しながら整理する

3
整理が終わり、設計書として作っていたため最後にtypescriptなどの型定義などの具体的な設計内容を加え始める
しかし、そのころには体力が尽き、かつそいった詳しい内容を考えたことがない、もともとその部分はaiでやろうと思っていたのもあって
gptに適当に作らせてしまう

4
その後、それをそれをそのままdocsに設計書として置き、実装書や仕様書などをつくらせるがそこも適当にやってしまう
できたドキュメントをもとにサービスを作成しだすが理想とは違うものに、また理想としていたものが頭の中で変化している
claudeとバイブコーディングをしつつdocsをふやしたり思想設計厳守で自分の入れたい機能をclaudeまとめがら右往左往していく

なんとなく実装ができるが、なかなかうまくいかない
コメントや実装結果をまとめたドキュメントとは実状が違い、形だけの実装になっている部分があることに気づく
それをaiに指示して探させるもうまくいかない
サービスの状態をaiに教えてもらっていたため、自身でサービスの実状がわかっておらず、もっと厳格に見るべきだということに気づき、
コードにかいてあるコメントを参考になんとなくファイルごとにレビューをしだす

指摘していくうちにそもそも完璧だと思っていたドキュメントがそうでもないことに気づき、docsの修正をaiと一緒に始める

なんとなくできたとおもったら、コメントでわかる、もしくはコメントだけではわからない修正が必要が必要なところがたくさんあることに気づき、
修正を頼むもうまくいかない

claudeにファイル構造や関係をまとめさせるもぐちゃぐちゃでわけがわからないから、webのclaudeとgithubリポジトリを参考に
ファイル構造や関係をまとめ直すように頼むプロンプトを作成させる

ファイル構造はなんとなく治ったがおかしな部分が多すぎて結局は微妙な感じに
