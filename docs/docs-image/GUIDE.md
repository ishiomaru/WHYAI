# 実装ガイド (GUIDE.md)

## 概要
本ガイドは、開発者が「親切心」によってシステムの設計思想を破壊することを防ぐための「禁止則 (Taboos)」と、技術的不確実性に対処するための「侵襲度縮退 (Fallback)」フローを定める。

## 1. Taboos (厳格な禁止事項)

いかなる理由があろうとも、以下の機能を実装してはならない。

### 🚫 The Teacher Trap (教師の罠)
*   **禁止**: AIに「正解」や「解説」を語らせること。
*   **理由**: 学習者が自ら構造を構築する機会を奪うため。
*   **検知**: PRに "explain", "teach", "answer" といった単語が含まれていないか確認せよ。

### 🚫 The Recommended Path (推奨ルート)
*   **禁止**: 特定のリソースや選択肢を「おすすめ」「重要」としてハイライトすること。
*   **理由**: システムの価値観を押し付けることになるため。
*   **検知**: UI実装において `.highlight`, `.recommended`, `font-weight: bold` 等が意味的に使われていないか確認せよ。

### 🚫 The Summary Shortcut (要約の近道)
*   **禁止**: 長い文章やドキュメントをAI要約して提示すること。
*   **理由**: 「読む」という行為の中で行われる構造化プロセスを代行してしまうため。
*   **検知**: `summarize()`, `shorten()` といったメソッドの使用を禁止する。

## 2. 侵襲度縮退 (Fallback Strategy)

AIがユーザーの意図を汲み取れない、または確信度が低い場合、システムは「知ったかぶり」をしてはならない。段階的に介入レベルを下げ、主導権をユーザーに戻す。

### Level 1: Strict Translation (通常)
*   AIは構造的事実を忠実に翻訳して提示する。

### Level 2: Raw Data Projection (確信度低)
*   **Trigger**: Intent Classificationのスコアが閾値を下回った場合。
*   **Action**: 意味解釈を放棄し、生の検索結果やデータをそのままノードとして配置する。「あなたの言ったことはこれですか？」という問いのみを添える。

### Level 3: Manual Override (解析不能)
*   **Trigger**: エラーが連続した場合、またはユーザーが拒絶反応を示した場合。
*   **Action**: AI介入を停止し、完全な手動操作モード（ホワイトボードモード）へ移行する。「システムはあなたの意図を理解できませんでした。手動で配置してください」と正直に告げる。

## 3. Review Checklist

すべてのコード変更において、レビュアーは以下を確認する義務がある。

- [ ] AIプロンプトは「Teacher」ではなく「Space Manager」になっているか。
- [ ] テンプレートへのフォールバック（安易な固定文言）が含まれていないか。
- [ ] UIは「評価」を含まない「事実」のみを表示しているか。
- [ ] エラー時に「知ったかぶり」をするロジックが含まれていないか。

## 4. 共存表示と段階的生成

### 4.1 共存表示ルール
- 表示コンポーネントは**迷子状態（M0-M5, RESOLVED）に基づいてルールベースで決定**
- AI判断は不要（Homeostatic Controllerが決定）
- sandbox生成は**RESOLVED状態のみ**（迷子状態が解消された場合）

### 4.2 RESOLVED状態
学習者が以下を理解している状態:
- 今どういう状況か
- 次に何のために何をするか
- その理由

### 4.3 段階的生成
LLMクエリは機能ごとに分離し、段階的に実行する:
1. 意図検出
2. ノード抽出
3. 選択肢生成
4. sandbox生成（RESOLVED時のみ）

> **重要**: 一括クエリは品質低下を招く。各ステップの出力を次のコンテキストとして使用。
