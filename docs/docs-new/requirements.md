## 2. サービス概要

### 2.1 サービスコンセプト

> **学習者の迷子状態と同期しながら、思考空間を再編・可視化・方向付けすることで、学習者が再び自分で考え、行動を生成できる状態へ戻すための構造生成サービス**

### 2.2 基本理念

本サービスは以下の3つの原則に基づく：

1. **教えない** - 知識を直接提供しない
2. **決めない** - 判断を代行しない  
3. **行動を代行しない** - 学習者自身の選択を尊重

### 2.3 サービスの目的

| 区分 | 説明 |
|------|------|
| **自走支援** | 外部入力（具体行動の集合）に対し、学習者自身の判断軸でそれを選択肢として認識し、取捨選択できる状態を実現 |
| **構造提供** | 現在地（事実）、選択肢（具体行動）、問い（思考トリガー）を返し続ける |

### 2.4 ターゲットユーザー

| ID | ユーザー種別 | 特徴 | 典型的な状況 |
|----|--------------|------|-------------|
| **TU-01** | IT学習初心者 | 何から始めればよいか分からない | 「プログラミングを勉強したい」が具体化できない |
| **TU-02** | 中級者の壁に直面した学習者 | 基礎は理解したが次のステップが不明 | チュートリアルは終えたが何を作ればよいか分からない |
| **TU-03** | キャリアチェンジ検討者 | 目的は漠然とあるが手段が多すぎる | Web開発かデータサイエンスか決められない |

> [!NOTE]
> 共通特性: 「情報は得られるが、判断ができない」状態にある学習者

### 2.5 ビジネス目標

#### 2.5.1 目標一覧

| ID | 目標 | 説明 |
|----|------|------|
| **BG-01** | 学習者の自走開始 | 学習者が迷子状態から解決状態へ遷移し、自発的にセッションを終了する |
| **BG-02** | 介入の効率性 | 過剰な操作子適用なしに解決状態へ導く |
| **BG-03** | リピート利用 | 解決後に新たな迷子状態で再利用される |
| **BG-04** | 離脱防止 | セッション途中での離脱を最小化する |

#### 2.5.2 測定方法

各目標の測定は、機能要件で定義された状態モデルと連携して行う。

| ID | 測定対象 | 測定方法 | 備考 |
|----|----------|----------|------|
| **BG-01** | R0-R5への遷移 | 「解決の観測」に基づき、操作子適用への有効反応を観測 | サービス内で観測可能な指標のみ使用 |
| **BG-02** | 操作子適用履歴 | O0-O5適用回数と、「破綻検知」のP1-P4発生回数を記録 | 破綻発生は非効率の指標 |
| **BG-03** | セッション再開 | 同一ユーザーが新規セッションを開始した回数を追跡 | ログイン機能利用者のみ測定可能 |
| **BG-04** | セッション終了パターン | 「明示的終了（U-OP-06）」vs「無応答による自動終了」の割合を比較 | 無応答終了 = 離脱と定義 |

#### 2.5.3 目標値

| ID | 目標値 | 根拠・決定方法 |
|----|--------|---------------|
| **BG-01** | 要調査 | β版運用で基準値を取得後に設定 |
| **BG-02** | 要調査 | 平均操作子適用回数の分布を分析後に設定 |
| **BG-03** | 要調査 | リピート率の業界水準を調査後に設定 |
| **BG-04** | 要調査 | β版運用で離脱率の基準値を取得後に設定 |

> [!IMPORTANT]
> 目標値は現時点では未設定。β版運用（想定期間: 3ヶ月）でベースラインデータを収集し、その後に具体的な数値目標を設定する。

### 2.6 成功の定義

#### 2.6.1 成功状態

本サービスの成功は以下の**観測可能な状態**として定義する：

| ID | 成功条件 | 観測方法 | 対応する機能要件 |
|----|----------|----------|-----------------|
| **SC-01** | 解決状態への遷移 | 「解決の観測」方法（操作子適用への有効反応）を満たす | R0-R5 |
| **SC-02** | 明示的なセッション終了 | 学習者がU-OP-06「もう大丈夫」を選択 | U-OP-06 |
| **SC-03** | 再利用 | 同一ユーザーによる新規セッション開始 | - |

#### 2.6.2 成功判定の原則

| 原則 | 説明 |
|------|------|
| **観測可能性** | サービス内で観測できる行動のみを成功指標とする |
| **非断定** | 成功判定はシステム内部処理であり、学習者に「成功しました」とは伝達しない |
| **可逆性** | 一度「成功」と判定しても、再び迷子状態に戻ることを許容する |

> [!CAUTION]
> 以下は成功の指標に**含めない**：
> - 学習者が「正解」に到達したかどうか
> - 学習者の理解度・習熟度の向上
> - 学習者の満足度（主観的評価）
> - サービス外での行動（観測不可能）

## 4. ユーザー要件

### 4.1 学習者の操作要件

学習者がシステムに対して行える操作を定義する。

| ID | 操作 | 説明 | 受け入れ基準 |
|----|------|------|------------|
| **U-OP-01** | テキスト入力 | 学習者は自由形式のテキストを入力できる | 学習者が入力したテキストがシステムに送信され、システムからの応答が提示される |
| **U-OP-02** | 選択肢の選択 | 学習者は提示された選択肢から1つ以上を選択できる | 複数の選択肢が提示され、学習者がいずれかを選択でき、選択結果が反映される |
| **U-OP-03** | 問いへの応答 | 学習者は提示された問いに対して応答できる | 問いに対する応答手段が提供され、応答後にセッションが進行する |
| **U-OP-04** | 応答の保留 | 学習者は問いに「答えない」「わからない」を選択できる | すべての問いに対して回避選択肢が提示される |
| **U-OP-05** | 構造の操作 | 学習者は提示された構造に対して並べ替え・除外・グルーピングを試みることができる | 構造の並べ替え・除外・グルーピングが可能であり、操作結果が反映される |
| **U-OP-06** | セッション終了 | 学習者は「もう大丈夫」を宣言してセッションを終了できる | 学習者がセッション終了を宣言でき、宣言後にセッションが終了する |

### 4.2 情報提示要件

システムが学習者に対して提示する情報を定義する。

| ID | 提示内容 | 説明 | 受け入れ基準 |
|----|----------|------|------------|
| **U-PR-01** | 構造の可視化 | 現在の思考空間の構造を視覚的に提示する | 思考空間の構造が視覚的に表現され、操作後に変化が反映される |
| **U-PR-02** | 選択肢の提示 | 具体的行動の候補を並列して提示する | 複数の具体的行動候補が同時に提示され、それぞれ選択可能である |
| **U-PR-03** | 問いの提示 | 思考を促す問いを提示する（判断・評価を含まない） | 問いが提示され、判断・評価を含む表現（「べき」「正しい」等）が含まれない |
| **U-PR-04** | 事実の明示 | 学習者の発言・選択から抽出した事実を提示する | 学習者の入力・選択が「事実」として再提示される |
| **U-PR-05** | 逃げ道の提示 | 「答えなくていい」「わからない」「違う気がする」選択肢を常に提示する | すべての問い・選択場面で回避選択肢が提示される |

> [!IMPORTANT]
> 提示順序は「事実の明示 → 問い」の順とする。逆順は誘導となり原則違反。

### 4.3 セッション要件

| ID | 要件 | 説明 | 受け入れ基準 |
|----|------|------|------------|
| **U-SS-01** | セッション開始 | 学習者はいつでも新規セッションを開始できる | 新規セッションを開始でき、空のセッションから始まる |
| **U-SS-02** | セッション中断 | 学習者はセッションを途中で中断できる | セッションを途中で離脱しても、状態が保持される |
| **U-SS-03** | セッション再開 | 学習者は中断したセッションを再開できる | 中断したセッションを前回の状態から再開できる |
| **U-SS-04** | 履歴参照 | 学習者は現在のセッション内のやりとりを参照できる | セッション内の過去のやりとりを参照できる |

## 5. 機能要件

### 5.1 核心機能: レイヤー構造

本サービスは4つのレイヤーで構成される：

#### 5.1.1 レイヤーA: 状態空間（Structure Space）
- **種別**: 静的構造・事実
- **機能**:
  - 学習者が存在する「思考空間」の全体像を表現
  - 要素・関係・可能性の全体集合を管理
  - 選択肢（全集合）の保持

#### 5.1.2 レイヤーB: 状態遷移（Structural Dynamics）
- **種別**: 構造への唯一の介入・空間変形運動
- **機能**:
  - 迷子状態の遷移管理
  - 空間の細分化・再編・焦点化
  - 学習者の「次の判断軸を生成できない状態」の明示的可視化

#### 5.1.3 レイヤーC: 問い（Cognitive Intervention）
- **種別**: 動的・学習者への唯一の介入
- **機能**:
  - 学習者の視線・思考方向への介入
  - 複数の目的候補を同時に浮かび上がらせる
  - 評価基準生成装置として機能

#### 5.1.4 レイヤーD: 学習者思考空間（Cognitive Space）
- **種別**: 静的・学習者の事実
- **機能**:
  - 思考の集合を保持
  - 観点・関心・仮説・不安の管理
  - 判断軸の元となる素材

### 5.2 迷子状態モデル

学習者の行動不能・思考停止・探索不能を6つの状態として定義：

| ID | 状態名 | 定義 | 主な症状 |
|----|--------|------|----------|
| **M0** | 目的不明型 | 行動の背後にある「なぜ」を説明できない | 「これでいいのか？」が消えない、判断軸1が生成不可 |
| **M1** | 状態空間未形成型 | 情報は存在するが構造化されていない | 何を知らないかが分からない、全体像が見えない |
| **M2** | 選択肢過多型 | 選択肢は見えているが比較・絞り込み不可 | 全部重要に見える、優先順位が付けられない |
| **M3** | 判断軸不在型 | 選択肢・目的はあるが選び方が不明 | AとBで悩み続ける、決断が偶然になる |
| **M4** | 目的-手段癒着型 | 手段が目的として扱われている | 学習は進むが前進感がない |
| **M5** | 目的漂流型 | 目的は明確だが行動と接続されていない | 行動しても前進感がない |

> [!IMPORTANT]
> 迷子状態は「支配的迷子状態」として常に**1つだけ**を扱う。他は「背景ノイズ」として保持。

---

### 5.3 解決状態モデル（Resolved State Model）

学習者が「迷子状態」から脱し、自走可能になった状態を定義する。

#### 5.3.1 解決状態の定義

> **学習者が自らの判断軸を用いて、次の具体的行動を選択・実行できる状態**

#### 5.3.2 迷子状態別の解決状態

| ID | 元の迷子状態 | 解決状態（観測可能な指標） |
|----|--------------|---------------------------|
| **R0** | M0: 目的不明型 | 学習者が「なぜこれをやるのか」を自分の言葉で表現できる |
| **R1** | M1: 状態空間未形成型 | 学習者が「何を知らないか」を特定し、探索領域を絞れる |
| **R2** | M2: 選択肢過多型 | 学習者が選択肢を比較する基準を言語化できる |
| **R3** | M3: 判断軸不在型 | 学習者が「この基準で選ぶ」と宣言し、選択を実行できる |
| **R4** | M4: 目的-手段癒着型 | 学習者が手段と目的を分離して認識できる |
| **R5** | M5: 目的漂流型 | 学習者が行動と目的の接続を説明できる |

#### 5.3.3 解決の観測

解決状態への遷移の推定は、**「操作子と状態推定の関係」の反応観測例**を使用する。

| 推定の種類 | 観測内容 | 意味 |
|-----------|----------|------|
| 迷子状態の推定 | 操作子適用 → 反応なし | その迷子状態（Mx）ではなかった可能性 |
| 解決状態の推定 | 操作子適用 → 有効反応あり | 対応する解決状態（Rx）に近づいた可能性 |

> [!IMPORTANT]
> 解決状態は「正解に到達した」ことを意味しない。**「自分で動き出せる状態に戻った」**ことを意味する。

> [!NOTE]
> 迷子状態の推定と解決状態の推定は、同じ操作子適用・反応観測の枠組みを使用する。これにより診断的アプローチの一貫性を保つ。

#### 5.3.4 セッション終了

セッションの終了は**学習者の意思表示**によってのみ行われる。

| 終了方法 | 説明 |
|----------|------|
| **明示的終了** | 学習者が「もう大丈夫」と宣言した（U-OP-06） |

> [!CAUTION]
> システムはセッション終了を「決定」しない。「わからない」選択肢が常に存在するため、学習者が継続を望む限りセッションは継続する。

> [!NOTE]
> サービスは学習者を「正解」に導く装置ではなく、**「自走可能な状態」に戻す装置**である。したがって、学習者が選んだ方向が「最適」かどうかは評価しない。

> [!CAUTION]
> **「判定」と「断定」の区別**
> - **判定（許容）**: システムが内部処理として状態を推定し、次の動作（操作子選択等）を決定すること
> - **断定（禁止）**: 「あなたは解決状態です」「あなたはM2です」のように、判定結果を学習者に伝達すること
>
> システムは解決状態への遷移を判定して介入を調整するが、その判定結果を学習者に断定として伝えてはならない。

### 5.4 視点操作子（問いの型）

判断・評価・結論を含まず、思考空間の配置・焦点・切り取り方を変える操作：

| ID | 操作子名 | 操作対象 | 問いの型（例） | 生成結果 |
|----|----------|----------|---------------|----------|
| **O0** | 目的生成操作子 | 潜在的関心・価値・欲求 | 「なぜそれをやりたいと思ったか」 | 一次目的ノード |
| **O1** | 状態展開操作子 | 到達プロセスの想像可能性 | 「ゴールの一つ手前は何？」 | 粗い状態グラフ |
| **O2** | 削減・制約操作子 | 選択肢集合 | 「今、選ばなくてよいものは？」 | 行動候補の縮退 |
| **O3** | 評価軸生成操作子 | 判断基準・価値関数 | 「何が分かれば前に進める？」 | 一時的な評価軸 |
| **O4** | 目的分離操作子 | 目的と手段の結合構造 | 「それは目的？それとも手段？」 | 目的ノードの再抽出 |
| **O5** | 経路可視化操作子 | 行動→目的の距離感 | 「今の行動は、目的のどこに効く？」 | 経路再接続 |

#### 5.4.1 操作子と状態推定の関係（診断的アプローチ）

操作子は**診断装置**として機能する。状態を先に判定して操作子を選ぶのではなく、操作子を適用した反応から状態を事後的に推定する。

| 操作子 | 有効反応が得られた場合の推定 | 反応の観測例 |
|--------|---------------------------|-------------|
| **O0** 目的生成操作子 | M0（目的不明型）だった可能性 | 学習者が「なぜ」を言語化し始めた |
| **O1** 状態展開操作子 | M1（状態空間未形成型）だった可能性 | 学習者が「次は何か」を想像し始めた |
| **O2** 削減・制約操作子 | M2（選択肢過多型）だった可能性 | 学習者が選択肢を絞り込んだ |
| **O3** 評価軸生成操作子 | M3（判断軸不在型）だった可能性 | 学習者が比較基準を言語化した |
| **O4** 目的分離操作子 | M4（目的-手段癒着型）だった可能性 | 学習者が「目的は別にある」と認識した |
| **O5** 経路可視化操作子 | M5（目的漂流型）だった可能性 | 学習者が行動と目的の接続を確認した |

> [!IMPORTANT]
> この表は「M0だからO0を使う」という処方的マッピングではない。
> 「O0を試して反応があれば、M0だった可能性が高い」という**診断的推定**である。

---

### 5.5 判断不能状態の検出（臨界点）

#### 5.5.1 臨界点の定義
> **同一の評価基準を用いて、異なる選択肢を評価しようとした結果、どれも「判断できない」状態が再現されたとき**

#### 5.5.2 観測対象（外に現れた構造的振る舞い）
- 並べ替えを試みたか
- 除外を試みたか
- グルーピングを試みたか

> [!CAUTION]
> 学習者の内面（理解度推定、自信の有無、認知負荷の推測）は**取得しない**

---

### 5.6 破綻検知と回復

#### 5.6.1 破綻タイプ

| ID | 破綻名 | 説明 |
|----|--------|------|
| **P1** | 空間不変型 | 操作子適用前後で構造変化なし |
| **P2** | 局所変形型 | 空間の一部は変形するが支配的迷子状態に影響なし |
| **P3** | 過剰拡散型 | 空間が広がりすぎ判断不能が増幅 |
| **P4** | 反転型 | 別の迷子状態へ遷移してしまう |

#### 5.6.2 連続破綻時の戦略

| Phase | 名称 | 発火条件 | サービスの行動 |
|-------|------|----------|---------------|
| 1 | 侵襲度縮退 | N回連続で空間変化なし | 新しい操作子を出さず事実だけを返す |
| 2 | 視点運動の可視化 | Phase 1後も応答停滞 | 視点そのものを対象化（正誤は言わない） |
| 3 | 主体返却 | 視点提示後も変化なし | 誘導を完全に止め主導権を返却 |

## 7. 禁止事項（サービス原則違反）

> [!CAUTION]
> 以下の行為は**絶対禁止**とする

### 7.1 思考代行の禁止
- 「この情報は初心者向け」
- 「重要度が高い」
- 「次はこれをやるべき」
- 情報の優先順位付け（意味的）
- 「あなたはいまM2です」のような状態断定

### 7.2 判断要求の禁止
- 「どうしますか？」
- 「何が問題ですか？」
- 「別の基準を考えましょうか？」

### 7.3 許容される行為
- 構造の再表現（分類・要約・位置づけ）
- 候補空間の生成（「ありうる目的群」「ありうる選択肢群」を並べる）

## 8. 設計原則

### 8.1 誤判定対策の4原則

| # | 原則 | 説明 |
|---|------|------|
| 1 | 状態を断定しない | 「もし今◯◯なら、この問いが効く」構造で仮説として扱う |
| 2 | 操作子を診断装置にする | 問いに対する反応で状態を明らかにする |
| 3 | 単発判定を避ける | 複数の操作子適用と反応観測から状態を推定する |
| 4 | 逃げ道を残す | 「答えなくていい」「わからない」「違う気がする」選択を常に提供 |

### 8.2 最重要設計結論

本サービスは：
- 正解の状態を当てる装置ではない
- **誤っても学習者を壊さない装置**

必要なのは：
- 判定より**再判定可能性**
- 精度より**可逆性**
- 誘導より**自己修復**

## 9. スコープ定義

### 9.1 スコープ内
- 判断軸1を生成させうる目的の支援
- 構造の提示・可視化・再編
- 迷子状態の検知と対応
- 外部情報の収集と構造ヒント抽出

### 9.2 スコープ外
- 理解度推定
- 動機推定
- 学習者評価
- 意味説明
- 判断軸1を生成できない目的

## 11. 用語定義

| 用語 | 定義 |
|------|------|
| 認知的地図 | 何を学ぶか、なぜ学ぶかを知ること（知識の集合ではない） |
| 判断軸1 | 全体空間から候補領域を切り出す探索空間の縮約機能 |
| 判断軸2 | 候補内での比較・微調整を行う選択の最適化機能 |
| 目的α（表層目的） | 学習者が今口にしているもの（例：Pythonを勉強したい） |
| 目的β（生成的目的） | 判断軸1を駆動しているもの（例：何かを作りたい） |
| 支配的迷子状態 | 行動生成を阻害している最大要因（常に1つとして扱う） |
| 解決状態 | 学習者が自らの判断軸を用いて次の具体的行動を選択・実行できる状態 |
| 操作子 | 思考空間の配置・焦点・切り取り方を変える操作 |
| 構成空間 | 学習者が「今、操作可能だと認識している対象と関係の集合」 |
| 破綻 | 操作子適用による誤判定（観測事象として扱う） |

## 12. 補足事項

### 12.1 目的の扱い方
- 目的は「確定」ではなく「仮置き」
- 信じない、しかし無視もしない
- **仮説として保持する**

### 12.2 問いの設計原則
- 答えやすい問い ✕
- 思考を促す問い △
- **同じ評価基準では答えが出ない問い ◯**

### 12.3 「問い」と「事実」の提示順序
1. 事実の明示（逃げ場のない構造）
2. 問い（意味の余地を開く）

> [!WARNING]
> 逆にすると、問いが誘導になり「言わされている」感覚が発生する
